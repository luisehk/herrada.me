How I build with agents

Smithy · in daily use since October 2026 · numbers read 2026-11-25

the idea

one person, many agents, one record

AI agents can write code faster than one person can follow. Smithy is my answer: a personal system where agents do the building and I can still see the design, the decisions and the state of everything.

a balanced approach

ten years on

In 2016 I started an agency called Vordem. Its home page put our way of working under one heading, “A balanced approach”: strategists, developers, designers and product managers on the same problem, looking for a simple and elegant answer. We were ten people and shipped 10+ products.

The workshop I run today works the same way, with agents in most of the seats. One shapes an idea into a work item with me. One argues with the design before any code exists. One builds. A panel of reviewers checks correctness, security, QA and UX from the diff and the evidence, and never sees the plan. The decisions stay with me.

the board

the life of a work item

The columns:

  1. Grooming
  2. Backlog
  3. Next up
  4. In dev
  5. In QA
  6. In code review
  7. To be deployed
  8. Done

A card moves only when something real happens: a claim, a gate verdict, a pull request marked ready, a merge, a deploy, an answer. There is no command to move a card.

Needs input is a flag over any column. It is raised only for a blocker, a design decision, a destructive action or a question of intent.

An item leaves grooming only when its definition is complete for its size: a problem, context and acceptance criteria, then a design, a test plan and risks for bigger items, plus a diagram and a design review for the biggest.

the loop

eight levels

Every work item plays the same eight levels, in this order. Each picture below is one still frame.

Shape

An idea becomes a work item with a problem, context, acceptance criteria and a test plan. Its mode is set here: autonomous or review.

Review the design

Bigger items get a written design and an adversarial review before any code exists.

Build

An agent claims the item, works in its own copy of the repo and opens a pull request.

Pass the gates

make ci on the exact commit. A gauntlet of reviewers for correctness, security, QA and UX, who see the diff and the evidence and never the plan. An end-to-end run against a real local stack. Each gate leaves a stamp: a verdict tied to a commit.

Gates: ci, review, qa, design-review, deploy. Verdicts: pass, pass with notes, blocked, needs human, skipped, error.

Land

An autonomous item merges and deploys when every stamp is green, and leaves a summary to read later. A review item stops at a ready pull request and waits for me.

Ask only what matters

Critical questions arrive with options, a recommended answer, the cost to reverse and what happens if I do nothing. The agent then moves to other work. Every other judgment call is made, logged with its reason and reviewed later.

Learn

On a fixed rhythm each session turns what it learned into a skill, a note or a new work item.

Pace

A governor starts new runs only when there is headroom, so a long night of work never hits a wall.

Calls feed the record. After a call with my partner an agent writes the notes and files the action items.

one real item

a speedrun in four splits

VP-0010, “Copy fix: stop promising a daily set until one exists”. The vim-puzzles dashboard still said “Daily vim puzzles” after the daily set was gone. An agent found the gap while grooming the app's backlog: the new About page would have repeated a promise the product no longer kept.

It raised one question for me, with two options and a recommended answer. I had told the agents not to get blocked, so the recommended answer was taken and logged for me to read.

Thirteen minutes later the fix was built and had passed CI. Fourteen minutes after that it had passed review. It was deployed four and a half hours after the decision. The line it left on the dashboard is the app's line today: “Vim puzzles, scored against par.”

rules

twelve decisions from the ledger, shortened

  1. Record decisions as short records. Bodies never change. A new record supersedes an old one.
  2. Columns are derived from facts.
  3. Convention over configuration: the standard make targets are the contract with every project.
  4. An item's mode is set at grooming: autonomous items land and deploy when green, review items wait for me.
  1. The window is a viewer. Every change goes through a session and the API.
  2. Reports are a first-class record.
  3. Every working session turns its lessons into skills.
  4. Gated pull requests land by default.
  5. Nothing waits for me unless it is destructive.
  6. Everything that waits on me lives in one list.
  7. Pace the agents with a governor.
  8. Calls feed the record: each transcript becomes a summary and work items.
